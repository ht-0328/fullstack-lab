# 公式スキル doc-coauthoring が使えないときの進め方

文書を書く段取りは、Anthropic が公開している公式スキル `doc-coauthoring` を正とします。出所は [anthropics/skills の skills/doc-coauthoring](https://github.com/anthropics/skills/tree/main/skills/doc-coauthoring)（Apache License 2.0）で、Claude Code ではプラグイン `example-skills@anthropic-agent-skills` に入っています（導入の手順は [.agents/README.md](../../../README.md) の「公式のスキル」）。

ここには、そのスキルを呼べない環境（プラグインを入れていない、Claude Code 以外のエージェント）で同じ進め方をするための要約だけを置きます。本文は書き写していません。公式スキルが更新されたら、そちらに従います。

## 3 つの段

1. **文脈を集める。** 書き手（ユーザー）が知っていて、文書を書く側が知らないことを埋めます。何を作るか、誰が読むか、読んだあと何ができればよいか、制約は何かを聞き、関係する資料（issue、既存の文書、契約、実装）を読みます。そのうえで、足りない点を番号付きの質問にまとめて聞きます。境界の場合や兼ね合いについて、基本の説明なしで質問できるようになったら、次へ進みます。
2. **節ごとに書いて直す。** いちばん分かっていない節から始めます。節ごとに、入れる候補を挙げ、残すものを書き手に選んでもらい、下書きを書き、指摘を受けて小さく直します。直すときは全文を書き直さず、該当の箇所だけを置き換えます。最後に全体を読み、無くしても困らない文を削ります。
3. **読者テストをする。** 文脈を持たない読み手（サブエージェント）に文書だけを渡し、読者が聞きそうな質問に答えさせます。答えられない質問、間違える質問、あいまいな箇所、書き手だけが知っている前提を見つけ、該当の節に戻って直します。読み手が質問に正しく答えられ、新しい抜けが出なくなったら終わりです。

このリポジトリで重ねる決まり（型は聞かない、決まっていないことと作る順序は issue に書く）は、[SKILL.md の「3. 文脈を集め、節ごとに書く」](../SKILL.md) にあります。
