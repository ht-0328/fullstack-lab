# ADR-0001 画面（Nuxt）は OpenAPI から型だけを生成し、HTTP の層は生成しない

| 項目 | 内容 |
|---|---|
| 発信日 | 2026-10-28 |
| 作成者 | ht-0328（Claude Code で作成） |
| 機密区分 | 公開可 |
| 保守責任者 | ht-0328 |
| 最終確認日 | 2026-10-28 |
| 想定読者（宛先） | 画面と BFF の間の呼び出し方を変える開発者 |
| この文書を読んだあと読者ができること | 画面側のクライアントを手書きのまま型安全にしている理由と、変える場合の影響を説明できる |

## 状況

業務環境では、画面と BFF の間も OpenAPI から TypeScript の型・DTO・コントローラーのインターフェースを生成していたが、画面が BFF を呼ぶクライアントは自前で書いていた。Nuxt と OpenAPI の相性が悪いのかという疑問があった。

| 項目 | 内容 |
|---|---|
| 課題 | SSR 時（Nuxt サーバー内）とブラウザ時で呼び先とヘッダーの扱いが違う。JWT とリクエスト ID は SSR 時に自分で転送する必要がある |
| 候補 | `openapi-generator` の `typescript-fetch` / `typescript-axios`（HTTP 層まで生成）、`openapi-typescript` + `openapi-fetch`（型だけ生成） |

## 決定

`openapi-typescript` で `paths` と `components` の型を生成し、`openapi-fetch` の薄い型付きクライアントを `useBff()` の中で組み立てる。HTTP の層は生成しない。

| 項目 | 内容 |
|---|---|
| 適用対象 | 画面から BFF への呼び出し（`web/frontend/app/composables/useBff.ts`） |
| 適用開始日 | 2026-10-28 |
| 対象外 | Kotlin 側のクライアント（成果物として配布。ADR-0002） |
| 決定者 | ht-0328 |

## 理由

| 判断基準 | 根拠 | 評価 |
|---|---|---|
| SSR との整合 | 生成クライアントが独自の HTTP 層（axios など）を持つと、`useAsyncData` との二重構造になり、呼び先の切り替えとヘッダー転送を外側で包み直す必要がある | 型だけ生成する方式なら `useBff()` の切り替えロジックがそのまま残る |
| 型安全 | `openapi-fetch` はパス・パラメーター・レスポンス・エラーの型を `paths` から決める | 項目名や型の誤りがビルド時に分かる |
| 業務環境との近さ | 業務では自前のクライアントだった | 自前のクライアントを型安全にした形に相当する |
| 学習の価値 | 「相性が悪い」のは HTTP 層まで生成する方式であることを、動く形で示せる | 疑問に答えられる |

## 結果と影響

| 方向 | 内容 | 影響する対象 |
|---|---|---|
| 良くなること | 契約を変えると画面側の型エラーとして現れる | 画面の変更 |
| 良くなること | SSR / ブラウザの切り替えと 401 時の誘導を 1 か所に保てる | `useBff()` |
| 悪くなること | `openapi-typescript` が TypeScript 5 系を要求するため、6 系を使えない | `web/frontend` の TypeScript |
| 悪くなること | 呼び出しのたびに `unwrap()` で `{ data, error }` を変換する | ページのコード |
