### 決まり側の課題

- W-2 が図（mermaid）のノードの文言にも及ぶかが決まっていない（1 回目）。
- AWS 化の文書では製品名と概念語（IAM、S3、ARN、state、STS、OIDC、作っては壊す）が一度に増える。architecture の「用語」に AWS と Terraform の語を足せば、フェーズ 4 以降の設計書は初出でリンクするだけで済む（1 回目）。
- W-9 で、「リポジトリ」（git と ECR）のような一般語の衝突は修飾があれば足りるのかが決まっていない（1 回目）。
- 外部の記事から取った技術的な主張（バージョンの下限など）を、確かめ済みと未確認のどちらとして書くかの決まりが無い。「確かめていない技術的な事柄は、出所と、確かめる段を書く」を W-4 か W-10 に足す（1 回目。ADR-0004 の評価でも出た）。
- F-5 の「名前で参照するときは必ずリンクにする」が、初出だけか毎回かが未解決（1 回目。[docs/README.md の記録](docs-README.md)にもある）。
- 「5 つのリポジトリ」の数え方が文書によって違う。AGENTS.md は集約リポジトリと領域の 4 つ、architecture の「用語」は集約リポジトリの参照先（領域の 4 つと図解のリポジトリ）を数えている（2 回目）。
- W-9 が、「回避策で動いたら A と B に書き足す」のような、これから書き足す先の指示も対象にするかが決まっていない（2 回目）。
