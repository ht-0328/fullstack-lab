# スモークテスト（`scripts/smoke-test.sh`）

この文書は、集約リポジトリの `scripts/smoke-test.sh` が確かめることを記す。スモークテストは、起動中のローカル環境に対して、入口（すべてのリクエストを最初に受けて振り分ける Nginx。[用語](../../architecture/README.md#用語)）から DB までの主要な経路を、実際に通して確かめるテストである。領域ごとのテスト（単体、Karate、Playwright）は 1 つの領域の中を確かめ、スモークテストは領域と入口をつないだ全体を確かめる。

このフォルダの全体と、文書で使う語の意味は [領域をまたぐ仕組みの全体像](README.md) にある。

## 実行の方法

開発者は、`docker compose up -d --build --wait` で全体を起動してから、集約リポジトリで `./scripts/smoke-test.sh` を実行する。スクリプトが使うコマンドは、`curl`、`grep`、`sed`、`docker` だけである。ポートとテスト用の利用者のパスワードは、`.env` から読む。

ログインは、スクリプトが `curl` で実際の画面の移り変わりをたどって行う。たどるのは、前段（アプリより手前で認証とセッションを担う oauth2-proxy。[用語](../../architecture/README.md#用語)）、Keycloak のログインのフォーム、コールバックの順である。使う利用者は、一般利用者の `alice` と `bob`、社員の `carol` と `dave` である（社員のロールは [Keycloak の realm `staff` の定義](keycloak-realm-staff.md)）。

## 確かめること

次の表は、スクリプトが出力するまとまりごとに、確かめることを示す。1 つでも失敗すると、スクリプトは失敗の件数を出して、終了コード 1 で終わる。

| まとまり | 確かめること |
|---|---|
| 入口と未認証アクセス | 入口が応答する。`/api/` は入口から 404 になる。未認証の画面は 302 でログインへ移り、未認証の BFF は 401 になる。未認証で偽のトークンのヘッダーを付けても 401 になる |
| ログイン | 4 人がログインできる。一般利用者は種別どおりに識別され、社員は `groups` クレームからロールを得る。一般利用者のセッションは社員のホストで使えず、ログイン後の偽のトークンのヘッダーは入口が上書きする。コンテナの中から、署名の無い JWT を BFF に直接送ると、401 になる |
| 認可 | 本人は登録と一覧ができる。他の一般利用者の詳細は 404 になる。`task-viewer` の社員は一覧と詳細を見られ、登録はできない。画面の出し分け用の値が、ロールどおりに返る |
| BFF から API、DB、外部サービスまで | 詳細に外部サービスの補足情報が入る。入力のエラーの 400 が画面の側まで返る。外部サービスの 500 と遅延では、詳細が 200 のまま `UNAVAILABLE` になる |
| タスクの完了 | 本人は完了にでき、他の一般利用者と `task-viewer` の社員は 403 になる。2 回目の完了でも完了日時が変わらない。`task-admin` の社員は他人のタスクも完了にできる。無いタスクの完了は 404 になる |
| 会員登録とパスワード変更 | 未認証で会員登録の画面を開けて登録でき、公開パスに偽のトークンのヘッダーを付けても未認証として描画される。登録済みのメールアドレスは 409、短いパスワードは 400 になり、社員のホストには公開パスが無い。パスワードは、現在のパスワードが違えば 403 になり、変更後は新しいパスワードでログインできる。社員はパスワードを変更できない |
| 画面 | 一覧、詳細、完了したタスクの詳細が、サーバー側の描画で、補足情報と完了日時まで出る |
| OpenAPI 仕様 | 未認証では Swagger UI がログインへ移り、ログイン後は開ける。契約のファイル（`bff.yaml`、`api.yaml`、`authz.yaml`、`auth.yaml` の 4 つ）が配信される |
| ログアウト | ログアウトのあとの BFF は 401 になる。IdP のセッションも終わり、再びログインのフォームが出る |

認証と認可の守りは、画面のボタンの有無ではなく、入口と BFF に直接送って拒否されることで確かめる。

## 実行される場面

スモークテストは、開発者が手元で実行するほか、[集約リポジトリの CI](ci.md) が PR と main への push のたびに実行する。
