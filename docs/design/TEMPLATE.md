## 解決する課題

> 書くこと: 最初の段落で、何を、誰のために、なぜ変えるかを 2〜4 文で言う（W-1）。表から始めない。
> 例: 利用者はタスクを登録できるが、片付いたタスクを「完了」にする手段が無い。一覧は増える一方で、まだやることと済んだことを見分けられない。この設計書は、タスクを完了にする操作を画面と API に足し、一覧と詳細で完了を見分けられるようにする。

次の表は、この変更の対象と規模、何ができれば完了かをまとめる。

| 項目 | 内容 |
|---|---|
| 対象 | 例: 一般利用者と社員の両方。画面は一覧と詳細、API はタスクの完了 |
| 発生規模（変えるリポジトリと契約の数） | 例: リポジトリ 4 つ（api、authz、web、集約）。契約 2 つの互換変更 |
| 利用者への影響（今できないこと、困っていること） | 例: 今はタスクを完了にできず、済んだタスクが一覧に残り続ける |
| 成功条件 | 例: 本人が詳細画面で「完了にする」を押すと完了日時が記録され、一覧と詳細に完了が出る。他人のタスクは完了にできない（403） |

## 採用案

> 書くこと: 採用する構成を 1〜2 文で言い切る。続けて要素ごとに、何を採用し、何を担当させるかを表にする。代替案との比較はここに書かず「比較した代替案」に書く（W-8）。
> 例: API にタスクの完了エンドポイントを足し、BFF が認可 API に `task:complete` を問い合わせてから呼ぶ。完了は冪等（何回呼んでも結果が同じ）にし、2 回目以降は現状を返す。

次の表は、採用案を要素ごとに分け、採用内容と責務を示す。

| 要素 | 採用内容 | 責務 |
|---|---|---|
| 例: API | 例: `POST /api/tasks/{id}/completion`。`completed_at` が空のときだけ更新し、既に完了なら現状を返す | 例: 完了日時の記録。同時に 2 回押されても 1 回しか記録しない |
| 例: BFF | 例: `POST /bff/tasks/{id}/complete`。先にタスクを取得して所有者を知り、認可 API に問い合わせ、許可なら API を呼ぶ | 例: 認可の問い合わせと、画面向けの `canComplete` の算出 |

### 契約の変更

> 書くこと: 変える `openapi/*.yaml` と、互換か非互換か（必須項目の追加・削除・型変更は非互換）。バージョンの上げ方と、呼び出し側の追従の順序。差分は OpenAPI の抜粋で示す。追加だけの互換変更なら、変更点の表だけでも足りる（F-4）。変えないなら「変えない」と理由を 1 行。
> 例: `api/openapi/api.yaml` を 1.0.0 → 1.1.0（互換。`Task.completedAt` と `POST /api/tasks/{id}/completion` の追加）。BFF は api-client 1.1.0 に追従する。

```yaml
# 例: api.yaml の抜粋
paths:
  /api/tasks/{id}/completion:
    post:   # 200 Task（既に完了なら現状を返す）/ 404
```

### 認可

> 書くこと: 新しい操作（`task:xxx`）が増えるなら、利用者の種別ごとの可否と、`authz/src/main/resources/application.yml` の差分。増えないなら理由を 1 行。

次の表は、利用者の種別ごとに新しい操作の可否を示す。社員はロールで、一般利用者は所有者かどうかで決まる。

| 操作 | 一般利用者 | 社員 `task-viewer` | 社員 `task-admin` | 備考 |
|---|---|---|---|---|
| 例: `task:complete` | 例: 自分のタスクのみ | 例: 拒否 | 例: 全件 | 例: `customer-actions` と `task-admin` に追加 |

### テスト

> 書くこと: どの層で何を確かめるか。層ごとに、対象と確かめることを書く。確かめないことがあれば「課題・申し送り事項」に書く。

次の表は、層ごとに何を確かめるかを示す。Karate は API を HTTP で呼んで確かめるテスト、Playwright はブラウザで画面を操作するテスト、スモークは集約リポジトリで全体を起動して主要な経路を通すテストである。認可の守りは画面のボタンの有無ではなく、直接呼んで 403 になることで確かめる。

| 層 | 対象 | 確かめること |
|---|---|---|
| 単体 | 例: BFF の `TaskViewService` | 例: 認可で拒否されたら API を呼ばない。完了済みなら `canComplete` が false |
| Karate | 例: API と認可 API | 例: 2 回目の完了で `completedAt` が変わらない。判定表に `task:complete` |
| Playwright | 例: 詳細画面 | 例: 本人は完了にできる。`task-viewer` はボタンが出ず、直接 POST で 403 |
| スモーク（集約） | 例: 入口から DB まで | 例: 本人 200、他人 403、存在しない ID 404 |
