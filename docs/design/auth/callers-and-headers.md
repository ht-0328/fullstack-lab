# 呼び出し元と受け取るヘッダー

この文書は、認証 API（一般利用者のアカウントの登録、参照、パスワード変更を行う API。[全体像](README.md)）の呼び出し元と、認証 API が受け取るヘッダーを記す。記すのは、呼び出し元、認証 API が行わないこと、受け取るヘッダーである。リクエストと応答の項目は、契約（領域同士の API の取り決め。[用語](../../architecture/README.md#用語)）の [auth.yaml](../../../auth/openapi/auth.yaml) にあるので、この文書には書き写さない。

この文書では、アプリを使う人を「利用者」、Keycloak（一般利用者のログインを受け付けてトークンを発行するサービス。[用語](../../architecture/README.md#用語)）に登録されたアカウントを「Keycloak のユーザー」と書き分ける。

## 呼び出し元

認証 API は、BFF（画面専用のサーバー側 API。[用語](../../architecture/README.md#用語)）からだけ呼ばれる。認証 API は、呼び出し元を認証せず、認可も行わない。入口（すべてのリクエストを最初に受けて振り分ける Nginx。[用語](../../architecture/README.md#用語)）には、認証 API へ転送する設定が無いので、ブラウザから認証 API へは届かない。

認証 API は、パスの `{id}` に渡された Keycloak のユーザーの ID を、そのまま操作の対象にする。ログイン中の利用者が自分の ID だけを指定できるようにするのは、BFF の役割である。

## 受け取るヘッダー

次の表は、BFF が認証 API に渡すヘッダーと、認証 API での用途を示す。利用者の ID や名前のヘッダーは受け取らない。

| ヘッダー | 中身 | 認証 API での用途 |
|---|---|---|
| `X-Request-Id` | 入口が付けたリクエストの ID | ログの各行に `requestId` として出す。Keycloak を呼ぶときも同じヘッダーに付ける。無ければ `-` とする |
