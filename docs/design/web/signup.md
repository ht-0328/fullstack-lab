# 会員登録（`POST /bff/signup`）

この文書は、BFF（画面専用のサーバー側 API。[用語](../../architecture/README.md#用語)）のエンドポイント `POST /bff/signup` の処理を記す。このエンドポイントは、一般利用者のアカウントを登録する。会員登録は、ログインしていない人が呼ぶ。

流れは [全体像の「会員登録」](README.md#会員登録) の図にある。

## 処理と応答

応答は 201 と、登録した利用者の ID とメールアドレスである。入力が不正なら 400、メールアドレスが登録済みなら 409 を返す。次の箇条書きは、図の各段の理由と条件を示す。

- BFF は、JWT（IdP が署名して発行するトークン。[用語](../../architecture/README.md#用語)）を要求しない（[JWT の検証の「未認証で呼べるパス」](jwt-verification.md#未認証で呼べるパス)。未認証で呼べる経路にするのは [仮定 13](../../architecture/README.md#仮定)）。ヘッダーに JWT が付いていれば検証し、通らなければ 401 を返す。ログインしていない人には、認可 API に渡す主体（利用者の ID、種別、ロール）が無いので、認可 API には問い合わせない
- 認証 API の `POST /auth/v1/customers` には、入力（メールアドレス、姓、名、パスワード）をそのまま渡す。Keycloak（一般利用者の IdP のソフトウェア。[用語](../../architecture/README.md#用語)）へのユーザーの作成は認証 API が行う
- 応答の利用者の ID とメールアドレスは、認証 API が返した値である。この ID は、ログイン後の JWT の `sub` と同じ値である
- BFF は、登録した人をログイン済みにはしない。登録のあと、画面が通常のログインへ案内する
- 409 は、メールアドレスが登録済みのときに認証 API が返したものを、BFF がそのまま返す

入力の検証の方法、エラーの形、ここに無いステータスコードは [エラー応答](error-responses.md) にある。

## テスト

次の表は、このエンドポイントについて確かめることを示す。Playwright は、ブラウザを操作して画面を確かめるテストで、集約リポジトリ（このリポジトリ fullstack-lab。[用語](../../architecture/README.md#用語)）で全体を起動して実行する。

| 層 | 場所 | 確かめること |
|---|---|---|
| 単体 | `web/bff/src/test/` の `AccountServiceTest` | 会員登録は認可 API に問い合わせずに認証 API を呼ぶこと。認証 API の 409 がそのまま伝わること |
| Playwright | `web/e2e/tests/` | 登録の操作（確かめる中身は [会員登録の画面の「テスト」](screen-signup.md#テスト)） |
