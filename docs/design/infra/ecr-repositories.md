# ECR のリポジトリ

ECR は AWS のコンテナイメージの置き場で、アプリのイメージをここに置く。ECR の中でイメージを置く単位もリポジトリと呼ぶので、git のリポジトリと区別して「ECR のリポジトリ」と書く。この文書は、ECR のリポジトリの名前と設定、置くデータ、費用の見込みを記す。ECR のリポジトリは、Terraform（AWS の構成をコードで書いて作る道具）の `infra/shared` で作る（[Terraform の state の置き場所](terraform-state-bucket.md)）。

このフォルダの全体と、使う語の意味は [インフラの全体像](README.md) にある。

## 名前と設定

次の表は、ECR のリポジトリの名前と設定を示す。

| 項目 | 内容 |
|---|---|
| 名前 | `fullstack-lab/nuxt`、`fullstack-lab/bff`、`fullstack-lab/api`、`fullstack-lab/authz`、`fullstack-lab/auth` の 5 つ |
| タグ | 上書き不可（`IMMUTABLE`） |
| 脆弱性の検査 | push 時に基本スキャン（無料の脆弱性検査）を行う |
| ライフサイクルポリシー | タグ付きの最新 5 個を残し、タグの無いイメージは 1 日で消す。5 個残すのは、デプロイで直前のイメージに戻せれば足りるためである |

どのリポジトリの GitHub Actions がどの ECR のリポジトリへ push できるかは、[push 用の IAM ロール](ecr-push-role.md)にある。

## 置くデータ

次の表は、ECR に置くデータの扱いを示す。

| 観点 | 内容 |
|---|---|
| 置くデータ | アプリのイメージを置く。個人情報は扱わない。イメージに秘密情報を含めない方法は、[push 用のワークフローの「イメージの中身」](push-image-workflow.md#イメージの中身)にある |
| 保持と削除 | イメージの保持は、ライフサイクルポリシーに任せる |
| 容量 | タグ付きのイメージは、ECR のリポジトリごとに最新 5 個までである |

## 費用の見込み

費用は ECR の保存料だけで、月 1 ドル未満に収まる（[ロードマップの「フェーズ」](../../roadmap/README.md#フェーズ)の 3）。

次の表は、費用が見込みを超えそうなときの動作を示す。予算の通知の設定は [architecture/ の「AWS アカウント」](../../architecture/README.md#aws-アカウント) にある。

| 失敗の条件 | 検知の方法 | 動作 | 開発者がすること |
|---|---|---|---|
| 月 10 ドルのコスト予算を超えそう | AWS Budgets（予算を超えそうなときに通知するサービス）がメールで通知する | 課金は止まらない | 何が費用を出しているかを Billing の画面で確かめ、要らないものを消す |
