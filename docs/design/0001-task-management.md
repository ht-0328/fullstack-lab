## 解決する課題

業務環境に近い経路（画面 → 入口 → BFF → API → DB / 外部サービス）で、一覧・登録・詳細の業務フローを動かして学べる題材を用意する。

| 項目 | 内容 |
|---|---|
| 対象 | タスクの一覧・登録・詳細表示と、期限日に関する外部サービスの補足情報 |
| 発生規模 | 学習用。利用者は数人、タスクは数百件以内 |
| 読者への影響 | 各技術の役割とリクエストの流れを、動くものを見ながら理解できる |
| 成功条件 | スモークテスト・Karate・Playwright が通る。外部サービスが落ちていても詳細画面が表示される |

## 制約と前提

| 区分 | 内容 | 根拠 |
|---|---|---|
| 制約 | ローカルは Docker Compose だけで完結する | 要件 |
| 制約 | 外部サービスは WireMock で代替し、スタブをリポジトリで管理する | 要件 |
| 制約 | 領域同士はソースを共有せず、OpenAPI の契約でつなぐ | [0003](0003-contracts-and-repositories.md) |
| 前提 | 利用者の ID と表示名は、認証済みの BFF が JWT から得て API に渡す | [0002](0002-authentication-authorization.md) |
| 前提 | 期限日の補足情報は「あれば表示する」情報で、無くても業務は成り立つ | 題材の設定 |

## 採用案

画面専用の BFF と業務 API を別サービスにし、外部サービスとの連携は API に閉じる。

| 要素 | 採用内容 | 責務 |
|---|---|---|
| 画面 | Nuxt 4（SSR + SPA） | 一覧・登録・詳細の表示。初回は SSR、その後はブラウザから同一オリジンの `/bff/*` を呼ぶ |
| BFF | Kotlin + Spring Boot | 認可 API への問い合わせ、API の結果を画面向けに集約、補足情報の縮退 |
| 認可 API | Kotlin + Spring Boot | 「この主体はこの操作をしてよいか」の判定 |
| API | Kotlin + Spring Boot | 入力検証、永続化（Flyway）、外部カレンダーサービスの呼び出し |
| DB | PostgreSQL 17 | `tasks` 表 |
| 外部サービスの代替 | WireMock | 祝日・営業日・500・遅延のスタブ |

### 影響するリポジトリ

| リポジトリ | 変更 |
|---|---|
| `api` | `tasks` 表（V1、V2）、`TaskController`、`CalendarClient`、WireMock のスタブ |
| `authz` | 操作 `task:list` / `task:read` / `task:create` の権限 |
| `web` | `TaskViewService`、`BffController`、ページ 3 つ |
| 集約 | Nginx のルーティング、スモークテスト |

### 契約

| 契約 | 版 | エンドポイント |
|---|---|---|
| `api/openapi/api.yaml` | 1.0.0 | `GET/POST /api/tasks`、`GET /api/tasks/{id}`、`GET /api/tasks/{id}/due-date-info` |
| `web/openapi/bff.yaml` | 1.0.0 | `GET /bff/me`、`GET/POST /bff/tasks`、`GET /bff/tasks/{id}` |
| `authz/openapi/authz.yaml` | 1.0.0 | `POST /authz/v1/decisions` |

### 認可

| 操作 | 一般利用者 | 社員 `task-viewer` | 社員 `task-admin` |
|---|---|---|---|
| `task:list` | 自分のタスクだけ（`ownerId` で絞る） | 全件 | 全件 |
| `task:read` | 自分のタスクだけ。他人のものは 404 | 全件 | 全件 |
| `task:create` | 可 | 不可（403） | 可 |

## 比較した代替案とトレードオフ

| 案 | 利点 | 欠点 | 採否の理由 |
|---|---|---|---|
| BFF を別サービスにする（採用） | 業務環境と同じ分担。画面が増えても再利用できる | サービスが 1 つ増える | 業務構成の学習が目的 |
| Nuxt のサーバールートを BFF にする | サービスが減り、TypeScript だけで書ける | Kotlin の知識が画面側で使えない。業務構成と離れる | 不採用。小規模なら十分成り立つ案 |
| API が画面向けの集約も担う（BFF なし） | 中継が減る | 画面の都合が業務 API に混ざる。認可の問い合わせ先が増える | 不採用 |
| 補足情報を必須にする（取れなければ詳細もエラー） | 実装が単純 | 外部障害で詳細が見られない | 不採用。「あれば表示」が題材の前提 |

## 失敗時の動作

| 失敗条件 | 検知方法 | システムの動作 | 利用者への影響 |
|---|---|---|---|
| 外部カレンダーが 5xx を返す、または 3 秒以内に応答しない | API の `CalendarClient` が例外化し、`WARN` を記録 | API は 502（ProblemDetail）。BFF は `dueDateInfoStatus = UNAVAILABLE` で詳細を返す | 詳細は見られる。補足情報だけ「現在取得できません」 |
| 認可 API が応答しない | BFF の `AuthzClient` が例外化し、`ERROR` を記録 | BFF は 503。操作は許可しない（fail-closed） | 一覧・登録・詳細が使えない |
| API が応答しない | BFF の RestClient が例外化 | BFF は 502 | 同上 |
| DB が落ちる | API のヘルスチェックが失敗 | API は再起動を繰り返す。復旧後に自動で戻る | 復旧まで使えない |
| 入力エラー | API の Bean Validation | 400（ProblemDetail）を BFF がそのまま返す | 画面に理由が出る |

## 技術観点の確認

該当しない観点は行ごと削り、該当しない理由を 1 行書いている（[docs の決まり](../README.md#共通の決まり)）。

### セキュリティと権限

| 観点 | 内容 |
|---|---|
| 認証 | 前段（oauth2-proxy / ALB）と BFF の JWT 検証。[0002](0002-authentication-authorization.md) |
| 認可 | BFF が操作の前に認可 API へ問い合わせる。API は BFF を信頼する |
| 秘密情報の保管 | `.env`（コミットしない）。AWS では Secrets Manager |
| 通信の暗号化 | ローカルは HTTP。該当しない。AWS では ALB で TLS 終端 |
| 監査ログ | 認可 API が判定結果と理由を記録。`X-Request-Id` でサービスをまたいで追跡 |

### データ

| 観点 | 内容 |
|---|---|
| 扱う個人情報 | IdP の `sub`（`created_by`）と表示名（`created_by_name`）。メールアドレスは保存しない |
| 保持期間と削除 | 無期限。学習用で削除要件が無い |
| 移行 | Flyway の V1（表の作成）、V2（表示名の列と索引）。既存のマイグレーションは変えず、新しい版を足す |
| 容量の見込み | 該当しない。数百件のため |

### 性能と可用性

該当しない。学習用で目標値を置いていない。外部呼び出しのタイムアウト（接続 2 秒、読み取り 3 秒）だけを決めている。

### 可観測性

| 観点 | 内容 |
|---|---|
| メトリクス | Actuator のヘルスチェックのみ |
| ログ | `[requestId=…]` で BFF・認可 API・API を追跡できる |
| アラート | 該当しない。学習用 |

### 展開と後始末

| 観点 | 内容 |
|---|---|
| 展開手順 | `./scripts/publish-clients.sh` → `docker compose up -d --build --wait` |
| 切り戻し | 前のイメージで起動し直す。マイグレーションは後方互換（列の追加のみ） |
| 互換性 | 契約のバージョンで管理。[0003](0003-contracts-and-repositories.md) |
| 廃止計画 | 該当しない |
